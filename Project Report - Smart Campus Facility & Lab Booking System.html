1. Abstract

Managing university shared infrastructure—including computing labs, seminar halls, auditoriums, and sports courts—requires automated conflict resolution and role-based policies. The Smart Campus Facility & Lab Booking System is a console-based Java application developed to demonstrate core Object-Oriented Programming (OOP) paradigms. It incorporates inheritance hierarchies, dynamic method dispatch, mathematical interval overlap conflict detection, and single-file flat database persistence.

2. Problem Statement & System Objectives

Ad-hoc manual booking leads to double-booking identical slots, students monopolizing computer labs without time limits, and unauthorized reservations of large auditoriums. This software enforces automated interval overlap validation, role-based session quotas, and permission checks.

3. Object-Oriented Architecture

  • Facility Hierarchy: Abstract class Facility extended by concrete classes Lab (workstations, OS, GPU), Hall (A/V, projector, AC), and SportsCourt (surface type, indoor/outdoor, floodlights).
  • User Hierarchy: Abstract class User extended by Student (restricted to 2-hour sessions) and FacultyMember (permitted up to 6 hours with auditorium booking authorization).
  • Booking Entity: Encapsulates reservation interval and conflict validation logic.

4. Core OOP Principles Applied

OOP ConceptApplication in System
AbstractionAbstract classes Facility and User define essential method contracts while concealing concrete implementation.
InheritanceLab, Hall, SportsCourt inherit from Facility; Student, FacultyMember inherit from User.
PolymorphismDynamic method dispatch computes quota limits and displays specialized facility specs based on runtime instance.
EncapsulationPrivate fields accessed exclusively via validated methods; interval overlap logic encapsulated in Booking.
Exception HandlingCustom exceptions (CampusBookingException, SlotUnavailableException, InvalidInputException) protect against conflicts.
